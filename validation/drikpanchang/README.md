# Parsed drikpanchang.com scrape data

Month-start dates parsed from drikpanchang.com's solar calendar pages,
1900–2050. **This is the committed distillate of a very expensive scrape** —
the raw HTML it came from is ~2.3 GB and lives under the gitignored
`scraper/data/`.

Re-creating any of these requires ~1,812 page fetches per calendar against a
site that rate-limits at 200 requests per IP, i.e. about **9 VPN switches per
file**. They are ~53 KB each. Committing them is cheap insurance.

## Files

| File | Calendar | Months |
|------|----------|--------|
| `bengali.csv` | Bengali, Bisuddhasiddhanta (`drik-arithmetic=modern`) | 1,812 |
| `bengali_suryasiddhanta.csv` | Bengali, Suryasiddhanta (`drik-arithmetic=suryasiddhanta`) | 1,812 |
| `tamil.csv` | Tamil | 1,812 |
| `odia.csv` | Odia | 1,812 |
| `malayalam.csv` | Malayalam | 1,812 |

Format: `month,year,length,greg_year,greg_month,greg_day,month_name`

All are for New Delhi with Lahiri ayanamsa — see `scraper/README.md` for the
exact cookie settings used.

## Relationship to the scraper

`scraper/solar/parse.py` writes its output to `scraper/data/solar/parsed/`,
which is gitignored along with the raw HTML. These are copies promoted into
version control. After a re-scrape, refresh them with:

```bash
cp scraper/data/solar/parsed/*.csv validation/drikpanchang/
```

## What consumes them

- `validation/suryasiddhanta/compare_flavors.py` and `fit_rule.py`
- `scraper/solar/compare.py` reads from `scraper/data/`, not here — it is part
  of the scrape pipeline rather than the committed record

## Not to be confused with

`validation/moshier/solar/*.csv` are **our computed references**, generated by
our own C code. The files here are **drikpanchang's published values**, the
external ground truth we validate against.
